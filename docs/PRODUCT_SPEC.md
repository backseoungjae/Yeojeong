# Yeojeong 제품 기준

한국 여행지를 찾고 저장해 날짜별 여행 일정을 만드는 앱이다. 이 문서는 현재 제공하는 기능과 지켜야 할 동작을 정리한다.

| 항목 | 내용 |
| --- | --- |
| 사용자 | 한국 여행을 계획하는 한국어·영어 사용자 |
| 플랫폼 | Android / iOS. 웹은 보조 실행·검증용 |
| 데이터 | 한국관광공사 TourAPI + 기기 내 SQLite |
| 계정 | 로그인과 자체 서버 없음 |
| 언어·테마 | 한국어·영어, 라이트·다크 |
| 정리일 | 2026-10-11 |

## 1. 핵심 사용 흐름

1. 지역을 고르거나 검색해 장소를 찾는다.
2. 상세 정보를 확인하고 관심 장소를 저장한다.
3. 여행 이름과 기간을 정한다.
4. 날짜별로 장소를 추가한다.
5. 방문 순서와 메모를 수정한다.
6. 저장한 일정을 여행 중 확인한다.

한 여행에 여러 지역의 장소를 넣을 수 있다.

## 2. 화면별 기능

| 화면 | 현재 제공하는 기능 |
| --- | --- |
| 홈 | 탐색 진입, 진행 중·가까운 예정 여행 이어보기, 최근 본 장소 |
| 탐색 | 전국·시도·시군구 조회, 목록 유형 필터, 검색, 추가 페이지 |
| 장소 상세 | 사진·주소·설명·이용 정보, 주소 복사·외부 연결, 저장·일정 추가 |
| 내 여행 | 여행 목록, 저장한 장소 목록과 지역·유형 필터 |
| 여행 생성·수정 | 이름·기간 선택, 기간 변경 |
| 여행 상세 | 날짜 이동, 장소 추가·삭제, 순서 편집, 메모, 여행 삭제 |
| 설정 | 언어·테마, 출처·버전, 최근 기록·전체 데이터 삭제 |

홈 지역 선택·테마 추천, 검색어 해제 버튼, 설정의 개발 도구 메뉴는 현재 제공하지 않는다. 지역 탐색은 탐색 화면에 유지한다.

## 3. 탐색과 상세 규칙

- 목록의 유형 필터는 관광지·문화시설·음식점이다. 전체 목록에는 다른 유형도 포함될 수 있다.
- 검색은 버튼·키보드 제출·최근 검색어 선택으로 실행한다. 입력 중에는 요청하지 않는다.
- 키워드 검색에는 지역만 적용하고 유형은 전체로 바꾼다. 신분류 선택 UI는 없다.
- 필터 편집은 열기·닫기를 전환한다. 취소하면 기존 조건을 유지하고 상위 지역 변경 시 하위 지역을 해제한다.
- 이전 요청이 늦게 끝나도 최신 결과를 덮어쓰지 않는다. 페이지 요청·장소 중복을 방지한다.
- 첫 검색의 통신·시간 초과·HTTP 5xx 실패 후 같은 조건을 제출하면 재요청한다. 진행 중 중복 제출과 인증·할당량·설정 오류의 같은 조건 재시도는 막는다. 추가 페이지 실패는 기존 목록을 유지한다.
- 상세 복귀 시 검색 조건·목록·스크롤을 유지한다.
- 사진·이용 정보만 실패해도 성공한 상세 정보는 유지한다. 사진·운영 시간·요금이 없으면 없음을 안내하고 추정하지 않는다.
- 복사·전화·홈페이지 연결은 유효한 정보와 명시적인 사용자 조작으로 실행한다.
- 최근 장소는 최대 20개, 최근 검색어는 최대 10개다. 처음에는 최신 3개를 보여주고 더보기·관리 모드의 개별/전체 삭제를 제공한다.

## 4. 여행과 저장 규칙

| 상황 | 기대 동작 |
| --- | --- |
| 여행 생성 | 공백뿐인 이름과 잘못된 기간은 저장하지 않음. 기본 시작·종료일은 서울 기준 오늘 |
| 날짜 선택 | 달력 사용. 새 시작일은 오늘 포함 이후, 종료일은 시작일 이상 |
| 과거 여행 수정 | 기존 과거 시작일을 자동 변경하지 않음 |
| 일정 날짜 이동 | 여행 기간 안의 날짜만 선택. 이전·다음 버튼은 가로 배치 |
| 같은 장소 추가 | 같은 여행·날짜에는 중복 금지. 다른 날짜에는 허용 |
| 순서 편집 | 편집 모드에서 위·아래 이동. 변경 즉시 저장 |
| 메모 편집 | 명시적으로 저장. 실패하면 입력을 유지하고 미저장 이탈 시 확인 |
| 기간 축소 | 범위 밖 각 항목의 이동·삭제를 선택. 미선택·충돌 시 저장 거부 |
| 여러 항목 저장 | 모두 성공하거나 모두 취소. 수정 버전 충돌·중간 실패에도 부분 저장 금지 |
| 장소 저장 해제 | 기존 일정과 참조 장소 정보는 유지 |
| 일정 삭제 | 일정에서만 제거. 장소 저장 상태는 유지 |
| 여행 삭제 | 확인 후 그 여행·일정·메모만 삭제 |
| 최근 기록 삭제 | 저장한 장소·일정에 영향 없음 |
| 전체 삭제 | 범위 안내·최종 확인 후 앱의 사용자 데이터와 조회 캐시 삭제 |

여행 날짜는 `YYYY-MM-DD`로 저장한 한국 여행의 달력 날짜다. 기기 시간대가 바뀌어도 다른 날짜가 되면 안 된다. 여행 상태는 서울의 오늘 날짜를 기준으로 하며 생성·수정 시각과 구분한다.

일정 카드는 정보 영역으로 상세에 진입하고 더보기에서 삭제한다. 메모는 편집할 때만 입력 영역을 펼친다. 선택 항목의 메모를 취소해도 다른 항목의 입력은 유지한다.

전체 삭제 중 신규·늦은 저장을 막는다. 성공 후 홈과 기본 설정으로 돌아가며 DB 스키마는 유지한다. 네이티브 사진 캐시 정리를 시도하지만 웹 브라우저 사진 캐시와 기기 사진첩은 삭제 대상이 아니다.

## 5. 언어와 오프라인

| 대상 | 처리 |
| --- | --- |
| 버튼·오류 안내 | 앱의 한국어·영어 번역 |
| 새 관광정보 | 선택 언어의 API 조회 |
| 여행 이름·메모·검색어 | 사용자가 입력한 원문 유지 |
| 저장한 장소 | 저장 당시 기본 정보와 원문 언어 유지 |
| 오프라인 일정 | 여행·순서·메모 열람·편집, 기본 장소 정보 열람 |
| 오프라인 사진·설명 | 사진은 캐시에 있으면 표시. 상세 설명·이용 정보는 영구 저장하지 않음 |

국문·영문 장소는 서비스와 콘텐츠 ID로 구분한다. 같은 숫자·이름·좌표로 두 언어의 장소를 합치지 않는다. 번역 연결이 확인된 자료가 없으므로 자동 연결과 언어 간 중복 감지는 제공하지 않는다.

공급자에서 장소가 사라지거나 통신이 실패해도 저장한 일정을 자동 삭제하지 않는다. 조회 캐시가 만료돼도 일정에서 사용하는 장소 정보는 유지한다. 앱이나 저장 공간을 삭제하면 기록을 잃을 수 있다. 서버 동기화·백업은 없다.

테마는 선택 전 시스템을 따르며 명시적으로 라이트·다크를 선택하면 저장하고 유지한다. 시스템 선택 버튼은 없다.

## 6. 공통 품질 기준

- 같은 버튼·입력·달력·오류 UI와 디자인 토큰을 재사용한다.
- 두 언어·테마와 큰 글씨에서 핵심 문구·버튼이 잘리지 않아야 한다.
- 버튼 이름·역할·상태와 이미지 설명을 제공하고 색상만으로 상태를 구분하지 않는다.
- 순서 변경은 드래그 없이 버튼으로 가능하며 모션 감소 설정을 반영한다.
- 초기 포커스가 늦게 실행돼 복귀 포커스를 덮어쓰지 않아야 한다. 정상 흐름과 빠른 메모 조작을 별도 검사한다.
- 로딩·빈 결과·첫 실패·추가 페이지 실패·부분 실패를 구분한다.
- 저장 실패를 완료로 표시하지 않고 기존 기록을 유지한다.
- 인증키·메모·여행 이름·정확한 위치를 로그에 남기지 않는다.
- 현재 오류 기록은 안전한 로컬 로그다. Sentry 전송은 없다.
- 관광정보·사진의 출처와 이미지 이용 조건을 보존한다.

## 7. API 기준

| 목적 | API |
| --- | --- |
| 국문·영문 | KorService2 / EngService2 |
| 목록·검색 | areaBasedList2 / searchKeyword2 |
| 기본 정보·이용 정보·사진 | detailCommon2 / detailIntro2 / detailImage2 |
| 지역 | ldongCode2 |

지역은 API에서 반환한 법정동 코드를 사용한다. 관광지·문화시설·음식점 코드는 국문 `12/14/39`, 영문 `76/78/82`다. 신분류 조회는 개발 진단에서 지원하지만 사용자 필터는 없다.

응답과 HTTP·API 결과 코드를 검사해 공통 장소 정보로 변환한다. 목록·상세는 5분, 지역은 24시간의 메모리 캐시와 개수 상한을 유지한다. 새 검색 결과의 앱 재실행 복원은 보장하지 않는다.

## 8. 검증 상태와 남은 과제

2026-10-10에 실행한 검증 기록을 요약했다. 이번 문서 축약에서는 재실행하지 않았다. 아래 핵심 기능은 구현되어 있으며 실기기 미검증을 미구현으로 분류하지 않는다.

| 구분 | 기록된 상태 |
| --- | --- |
| 자동 테스트 | 103개 통과. 날짜·검색·저장·실패 복구 등. API 목업·실제 Node SQLite |
| 타입·린트 | 통과 |
| 웹 사용 흐름 | 생성·편집·오프라인 저장 데이터 복원·전체 삭제 통과. 실제 SQLite WASM |
| 웹 품질 | 언어·테마·좁은 화면·글씨 모의 확대·포커스·오류 처리 통과 |
| 실제 API·사진 | 2026-10-08~09 일부 표본의 CLI 조회·HTTPS 다운로드 확인 |
| Android | 사용자 수동 확인 보고 있음. 최신 수정의 항목별 결과는 추가 필요 |
| iOS·네이티브 접근성·성능 | 실기기 검증 필요 |

자동·브라우저 API와 브라우저 사진은 목업이다. 웹의 모의 글씨 확대·포커스 검사는 기기의 실제 설정·낭독기 확인을 대신하지 않는다. 웹 검증 중 로컬 서버는 접근 가능했으므로 전체 웹 앱의 오프라인 새 부팅을 보장하지 않는다. Android/iOS export 성공은 설치형 빌드 동작 확인과 다르다.

### 남은 실기기 확인

- 최신 APK에서 탐색 → 저장 → 여행 생성 → 순서·메모 수정 → 재실행
- 비행기 모드의 앱 시작·일정 편집·재실행
- 기간 축소·중복 장소·취소·전체 삭제와 네이티브 사진 캐시
- 메모의 빠른 입력·취소·계속 편집과 포커스 복귀
- 한국어·영어, 실제 큰 글씨, TalkBack·VoiceOver
- 기존 설치 DB 업그레이드, iOS와 기기 성능

기기·OS·빌드와 결과를 기록한 뒤 검증 상태를 갱신한다.

### 현재 제공하지 않는 기능

로그인·서버 동기화·백업·내보내기, 지도·주변 탐색·자동 경로, 방문 시간·이동 시간, 드래그 정렬, 사진 업로드, 관광 콘텐츠 전체 다운로드는 없다. 언어 간 장소 연결·신분류 필터·백업은 검토 후보이며 별도 범위 합의 후 진행한다.
