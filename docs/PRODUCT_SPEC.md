# Yeojeong 최종 제품 기준

- 제품: Yeojeong / 여정
- 기준일·문서 버전: 2026-10-11 · 1.2
- 코드 기준: `1d08b15` 및 현재 작업 트리의 `app.json`, `eas.json`
- 목표 플랫폼: Android / iOS. 웹은 보조 실행·검증 환경이며 SQLite 호스팅 제약이 있다.
- 언어: 한국어 / 영어
- 상태: MVP 핵심 기능 구현 완료. 자동·브라우저 검증 완료와 네이티브 항목별 미검증을 분리한다.
- 문서 성격: 현재 제품 동작·범위·수락 기준. 구현 구조·명명·작업 절차는 `AGENTS.md`가 관리한다.

## 1. 목적과 사용자

한국의 관광지를 발견하고 관심 장소를 날짜별 여행 일정으로 연결한다. 전국 여행을 계획하는 한국어 사용자와 한국을 방문하는 영어 사용자가 주요 대상이다. 여러 지역의 장소를 같은 여행에 추가할 수 있으며, 로그인을 요구하지 않는다.

여행·방문 순서·메모·저장한 장소·최근 기록·설정은 기기 SQLite에 보관한다. 새로운 관광정보 조회에는 네트워크가 필요하지만, 이미 저장한 일정과 기본 장소 스냅샷은 로컬에서 사용할 수 있다. 관광정보에 없는 평점·인기 순위·운영 정보를 만들어 표시하지 않는다.

### MVP 범위 제외

로그인·클라우드 동기화·자체 백엔드, 지도·현재 위치 권한·거리 계산·자동 경로, 방문 시간·이동 시간, 드래그 정렬, 사용자 사진 업로드, 전체 관광 콘텐츠 오프라인 다운로드, 장소 번역 연결 자동 추론은 제공하지 않는다. 내보내기·백업·복원 가져오기도 미구현이다. 앱 또는 저장 공간을 삭제하면 로컬 기록을 잃을 수 있다.

## 4. 화면별 현재 동작

### 4.1 홈

- 탐색·내 여행 진입을 제공한다. 별도의 홈 지역 선택·테마 추천은 표시하지 않는다.
- 서울 기준 진행 중 여행을 우선하고, 없으면 가장 가까운 시작일의 예정 여행을 이어보기로 표시한다. 같은 상태·시작일은 안정적인 ID로 정렬하며 지난 여행은 이어보기 대상이 아니다.
- 해당 여행이 없으면 새 여행 생성 동작을 제공한다.
- 최근 장소는 기본 최신 3개 카드, 더보기/접기, 관리 모드의 개별·전체 삭제를 제공한다. 개별 삭제 X는 카드 안에 표시한다. 상세로 이동하며 저장·일정 추가는 상세에서 수행한다.
- 최근 기록 삭제는 저장 장소·일정에 영향을 주지 않는다. 전체 데이터 삭제 결과/실패 안내를 표시한다.

### 4.2 탐색

- 전국 기본 목록, API가 반환한 시도·시군구 코드, 전체/관광지/문화시설/음식점 목록 유형을 제공한다. 기타 유형은 전체에 포함될 수 있다.
- 필터 편집 버튼은 열림/닫힘을 전환한다. 편집 중 값과 적용 조건을 구분하며, 취소는 기존 조건을 유지한다. 상위 지역 변경은 하위 선택을 해제한다.
- 검색은 버튼·키보드 제출·최근 검색어 선택에서 실행한다. 입력만으로 요청하지 않는다. 원문 검색어는 자동 번역·대소문자 변환하지 않는다.
- 검색 제출은 유형을 전체로 초기화한다. 검색 중 유형 선택은 비활성화한다. 지역 조건만 검색 요청에 결합한다.
- 적용 조건·검색어를 표시한다. 지역·유형 개별 해제와 전체 초기화를 제공하되 검색어 해제 전용 버튼은 없다.
- 첫 요청의 네트워크·시간 초과·HTTP 5xx 실패 후 같은 조건을 명시적으로 제출하면 새 첫 페이지 요청을 실행한다. 진행 중 중복 제출은 추가 요청을 만들지 않는다. 같은 조건 적용·화면 복귀·입력 변경만으로 자동 재시도하지 않는다. 인증·할당량 오류 상태의 같은 조건 제출도 새 요청을 실행하지 않는다.
- 추가 페이지 실패는 기존 목록과 성공 페이지 번호를 유지한다. 재시도 가능한 오류에는 명시 재시도를 제공한다. 인증·할당량·설정 오류에는 재시도 버튼을 제공하지 않는다.
- 장소 ID로 페이지 중복을 제거한다. 상세 복귀는 검색 조건·목록·스크롤을 유지한다. 언어 변경은 현재 지역·원문 검색어를 유지하며 해당 서비스의 콘텐츠를 조회한다.
- 최근 검색어는 최대 10개, 기본 최신 3개, 더보기/접기·관리 모드의 개별/전체 삭제를 제공한다.

### 4.3 장소 상세·저장 목록

- 기본 정보와 사진은 독립 조회하고, 검증된 기본 정보의 유형으로 이용 정보를 조회한다. 기본 실패 시 이용 정보는 대기한다. 성공 영역은 부분 실패로 지우지 않는다.
- 이름·주소·설명·전화·홈페이지·이용 정보·공급자 수정일·출처를 제공된 범위에서 표시한다. 누락·빈 사진·형식 오류·정상 빈 기본 정보를 구분한다.
- 사진은 한 장씩 contain으로 표시하고 이전/다음 이동을 제공한다. 사진 API 실패/빈 응답은 기본 정보·스냅샷 대표 사진을 시도하며 캐시가 없거나 로딩 실패하면 대체 영역을 표시한다.
- API HTML은 정리된 Text로 표시한다. 홈페이지는 검증된 단일 HTTP(S), 전화는 단일 유효 번호만 외부 연결한다. 주소 복사·외부 연결 실패를 성공으로 표시하지 않는다.
- UI 언어와 장소 서비스 언어가 다르면 원문 언어를 안내한다. 같은 숫자 ID로 다른 언어 서비스의 상세를 요청하지 않는다.
- 저장·해제는 상세 이동과 별도 조작이다. 저장 당시 기본 정보·기록 시점을 보존한다. 상세 성공 또는 로컬 기본 정보 표시 시 최근 장소를 기록한다. 최근 장소는 최대 20개다.
- 내 여행의 저장한 장소 영역에서 저장 항목의 지역·유형을 필터링하고 해제하거나 여행 일정에 추가한다. 지역 API 실패 시 로컬 목록을 유지하고 저장 코드로 안내한다.
- 저장 해제로 이미 추가된 일정·참조 스냅샷을 제거하지 않는다.

### 4.4 여행 생성·목록·수정

- 이름 앞뒤 공백을 제거하며 빈 이름·실재하지 않는 날짜·종료일 이전 시작일 관계 오류를 거부한다. 여러 지역의 여행지를 같은 여행에 추가할 수 있다.
- 새 여행 시작일·종료일은 서울 기준 오늘이다. 공통 달력으로 선택하며 시작일은 오늘 이전을 새로 선택할 수 없다. 수정 화면의 기존 과거 시작일은 자동 변경하지 않는다.
- 종료일은 시작일 당일 이후만 선택한다. 시작일이 종료일을 넘어가면 종료일을 새 시작일로 맞춘다.
- 목록은 서울 기준 진행 중·예정·지난 여행을 구분하고 이름·기간·일정 항목 수를 표시한다.
- 장소 상세/저장 목록에서 여행 → 날짜 → 추가를 제공한다. 여행이 없으면 생성하고 원래 추가 흐름으로 복귀한다.
- 여행 기간 축소는 범위 밖 각 항목에 이동 날짜 또는 삭제를 선택하게 한다. 미선택·범위 밖 이동·같은 날짜 같은 장소 충돌은 전체 저장을 거부한다.
- 실제 날짜가 유지되는 항목을 우선하고 이동 항목은 대상 날짜 끝에 기존 순서대로 추가한다. 기간·이동·삭제는 하나의 트랜잭션이다. 취소·실패·수정 버전 충돌은 기존 영속 기록을 유지한다.
- 여행 입력의 미저장 이탈을 확인한다. 삭제는 확인 후 해당 여행·일정·메모만 삭제하며 저장/최근 기록은 유지한다.

### 4.5 여행 상세·일정 편집

- 실제 날짜와 Day 번호를 표시한다. 이전/다음 날짜 버튼은 가로 배치하며 끝 날짜에서는 비활성화한다.
- 확인 날짜 달력은 여행 기간의 양 끝을 포함해 범위 안만 선택한다. 기간 변경으로 선택 날짜가 범위 밖이면 새 시작일로 조정한다.
- 같은 여행·날짜·공급자 식별자의 중복 추가를 막는다. 같은 장소의 다른 날짜 방문과 다른 지역 장소 추가는 허용한다.
- 카드의 장소 정보 영역으로 상세를 연다. 삭제는 더보기에서 수행하며 불필요한 메뉴 제목은 표시하지 않는다.
- 순서 편집 모드에서만 위·아래 버튼을 표시한다. 첫/마지막의 범위 밖 이동은 비활성화한다. 순서는 즉시 저장하며 날짜 변경 시 편집 모드를 종료한다.
- 메모는 저장 내용과 추가/수정 진입을 제공한다. 편집 시 하나의 장소별 메모 레이블·입력·저장 영역을 보여준다. 저장 성공은 접고 실패는 draft를 유지한다.
- 선택 항목의 메모 변경 취소는 그 항목의 미저장 내용만 버린다. 계속 편집 시 해당 취소 버튼으로 포커스를 복귀하고, 완료/닫힘 시 메모 진입 버튼으로 복귀한다. 새로운 영역·복귀 시 오래된 초기 포커스 예약을 취소한다.
- 날짜·화면 이동 전 미저장 메모를 확인한다. 다른 항목의 draft를 조용히 버리지 않는다.
- 일정 삭제는 일정에서만 제거하며 장소 저장 상태를 유지한다.

### 4.6 설정·전체 삭제

- 최초 언어는 기기의 첫 언어가 한국어 계열이면 한국어, 나머지는 영어다. 명시 선택을 저장하고 재실행 후 유지한다.
- 선택 전에는 시스템 테마와 변경을 따른다. 명시 라이트/다크 선택 후에는 고정하며 SQLite에 저장한다. 현재 적용 테마를 선택 상태로 표시한다.
- 최근 장소·최근 검색어 전체 삭제, 출처·이미지 이용 안내·버전, 기기 글자 배율·모션 감소·낭독기 상태 안내를 제공한다. 웹의 낭독기 상태는 확인 불가로 표시한다.
- 전체 삭제는 여행·일정·메모·저장·최근·설정·스냅샷·앱 조회 캐시의 범위·개수를 알리고 별도 최종 확인으로 실행한다.
- 수락된 작업 뒤 삭제하며 삭제 중 신규 작업·이전 세션의 늦은 저장을 거부한다. 사용자 테이블·ID 순서는 트랜잭션으로 비우고 스키마 v3는 유지한다.
- 네이티브는 Expo 이미지 캐시 정리를 시도한다. 웹 브라우저 HTTP/사진 캐시는 앱의 삭제 범위 밖임을 안내한다. 앱 번들·기기 사진 보관함·다른 기기 기록은 대상이 아니다.
- 성공 후 홈·새 세션·기기 언어·시스템 추종으로 복원한다. 실패는 DB 롤백·재시도 안내이며 사진 캐시는 먼저 정리될 수 있다. 저장 매체의 보안 소거를 보장하지 않는다.
- 개발 갤러리·진단·오류 경로는 개발 모드 직접 접근만 허용한다. 설정에 개발 메뉴는 없고 릴리스 직접 경로도 차단한다.

### 5.2 언어·식별·캐시

- 공급자 식별자는 `tourapi:<서비스>:<콘텐츠 ID>`다. 번역 연결 필드가 검증되지 않아 언어 간 자동 연결·중복 감지를 보장하지 않는다. 이름·좌표·oldContentid로 병합하지 않는다.
- UI 번역과 관광 콘텐츠 조회는 분리한다. 새 탐색은 선택 언어의 서비스, 저장/일정은 원문 스냅샷과 그 서비스의 상세를 사용한다. 사용자 입력은 그대로 유지한다.
- 캐시 키는 서비스·언어·엔드포인트·검색어·지역·유형·분류·정렬·페이지를 포함한다. 같은 요청은 공유하며 모든 소비자가 취소되면 통신을 중단한다. 실패는 값 캐시로 남기지 않는다.
- 목록·상세 기본/이용/사진은 각 5분·50개, 지역은 24시간·50개 메모리 캐시다. 언어 복귀용 화면 스냅샷은 최대 12개이고 만료된 페이지는 재사용하지 않는다. 재실행의 검색 결과 복원을 보장하지 않는다.

### 5.3 로컬 모델·트랜잭션

| 모델 | 핵심 정보·정책 |
| --- | --- |
| PlaceSnapshot | 원문 기본 장소·서비스·ID·출처·대표 사진 주소·기록 시점. 상세 설명·이용 정보는 저장하지 않음 |
| SavedPlace | 장소 ID·저장 시각. 서비스/콘텐츠 조합 중복 방지 |
| Trip | 이름·달력 시작/종료일·타임스탬프·수정 버전 |
| ItineraryItem | 여행·실제 날짜·장소·순서·메모. 날짜별 장소/순서 고유 제약 |
| RecentPlace / RecentSearch | 최근 순서, 각각 최대 20/10개 |
| Preferences | 언어·명시 라이트/다크 선택 |

`yeojeong.db`의 버전 1은 스냅샷·저장·최근·설정, 버전 2는 최근 순서·인덱스·개수 제한, 버전 3은 여행·일정·외래 키·고유 제약·날짜 범위 트리거다. 각 마이그레이션은 트랜잭션으로 실행하며 미래 버전을 덮어쓰지 않는다. 초기화 실패에 DB 삭제로 대응하지 않는다.

한 연결의 큐로 읽기/쓰기를 직렬화하며 순서 교환·기간 재작성·삭제는 트랜잭션이다. DB 커밋 후 화면 상태를 반영한다. 저장 해제·일정 삭제·최근 삭제는 독립적이며 일반 캐시 만료·조회가 참조 스냅샷을 지우거나 덮어쓰지 않는다.

여행 날짜는 `YYYY-MM-DD` 달력 값이고 날짜 연산·포맷은 시간대 이동을 피한다. 오늘과 여행 상태는 `Asia/Seoul` 기준이다. 생성·수정 시각은 별도 타임스탬프다. 기존 과거 날짜의 저장과 UI에서 과거 시작일을 새로 선택할 수 없는 제약을 구분한다.

### 5.4 오프라인·웹

오프라인 사용 범위는 로컬 여행·방문 순서·메모·기본 스냅샷이다. 기본 API 실패 또는 정상 빈 응답에서도 로컬 기록을 유지하며 기록 시점·최신 확인 불가를 안내한다. 공급자 콘텐츠 삭제로 사용자 일정을 자동 삭제하지 않는다. 사진은 기존 캐시가 없으면 대체 표시하고 설명·운영 시간·요금을 추정하지 않는다.

웹 SQLite는 WASM·Worker·교차 출처 격리·적절한 MIME이 필요하다. COOP same-origin / COEP credentialless를 개발·검증 서버에 제공한다. Web Locks 지원 환경에서는 한 문서의 DB 소유권을 조정하고 다른 창은 5초 대기 후 안내·재시도한다. 종료 시 연결을 정리한다. Web Locks 미지원 여러 창·다른 브라우저·전체 웹 오프라인 부팅은 미검증이다.

## 6. 디자인·접근성·보안 수락 기준

- 공통 토큰과 기본 UI를 사용하고 두 언어·두 테마의 길이·색상을 고려한다. 현재 공통 UI는 Text, Button, IconButton, TextField, DateField, Chip, Loading, Skeleton, EmptyState, ErrorState, ConfirmationPanel 등이다.
- 핵심 조작에 역할·레이블·선택·비활성·오류·완료 상태를 제공한다. 의미 이미지 설명, 별도 저장 조작, 최소 터치 영역 토큰과 색상 외 상태 표현을 유지한다.
- 일반 텍스트 대비 4.5 이상·입력/포커스 경계 대비 3 이상은 토큰 자동 테스트로 확인한다. 모든 실제 화면 조합의 접근성 인증을 의미하지 않는다.
- 시스템 글자 확대·모션 감소·낭독기 변경을 반영하는 코드는 구현했다. 핵심 흐름의 TalkBack·VoiceOver 완수는 여전히 네이티브 수락 기준이다.
- 초기/복귀 포커스는 공통 예약 취소 규칙으로 처리한다. 정상 완료 조건과 빠른 조작을 분리해 검사한다. 네이티브 접근성 이벤트의 실제 포커스·낭독은 미확인이다.
- 실제 키·개인정보를 코드·문서·이미지·로그에 포함하지 않는다. 환경변수는 EXPO_PUBLIC_TOUR_API_KEY와 선택적 KO/EN 전용 키, 예제 값은 빈 값이다. 클라이언트 키 은닉을 주장하지 않는다.
- ErrorBoundary와 고정 이벤트·영역·분류·시각의 로컬 로그는 구현했다. 외부 Sentry 전송은 미구현이며 원본 오류·인증 URL·사용자 메모를 전송하지 않는다.
- 관광정보·이미지는 한국관광공사 TourAPI 출처를 표시하고 원본·이용 유형을 보존한다. 제한된 CDN 경로만 HTTPS로 정규화하며 변경금지 이미지의 가공 허용을 추정하지 않는다.

### 7.3 실제 API·이미지 표본 — 기존 근거

2026-10-08~09의 기존 CLI 실행 기록과 표본 결과 파일을 확인했다. 이번 문서 작업에서는 실제 TourAPI·CDN을 재호출하지 않았다. curl은 TLS 검증을 유지했다. 다음은 표본 관찰이며 공급자 전체 데이터·현재 응답·실기기 렌더링을 보장하지 않는다.

- 두 서비스의 서울 표본에서 관광지·문화시설·음식점 유형, 목록·기본 상세·이용·사진 조회를 확인했다. 정상 빈 사진과 정보 누락도 관찰했다.
- 시도와 서울/세종 하위 지역 표본을 조회했다. 세종 반환 코드는 36110이었으며 36 대조 요청은 빈 결과였다. 코드 길이를 추정하지 않는다. 공급자 명칭 관찰을 현재 행정체계에 대한 별도 검증으로 해석하지 않는다.
- 키워드와 상위 신분류의 조합은 표본 확인했지만 2·3단계·세 공통 유형의 대응은 미검증이다. 현재 사용자 UI의 유형 검색 지원 근거가 아니다.
- 동일 명소의 국문/영문 콘텐츠 ID가 다른 표본을 확인했으며 번역 연결을 확정할 필드는 확보하지 못했다. 공급자 전체에 연결 정보가 없다는 결론은 내리지 않는다.
- 잘못된 테스트 키의 인증 오류 envelope를 확인했다. 실제 계정의 할당량 초과는 유도하지 않았다. 일일 할당량·남은 승인 트래픽은 계정 대시보드 미확인이다.
- 기존 전국 관광지 20건×2페이지×2서비스 CLI 4회와 CDN 이미지 GET 표본 기록도 확보되어 있다. HTTPS 사진 다운로드·일부 Chrome 디코딩은 네이티브 사진 표시와 구분한다.
- 필수 필드 손상·XML·다양한 할당량 오류·취소·부분 장애의 자동 검증은 목업이다. 웹 실제 API CORS는 미검증이다.

### 7.4 성능 근거의 한계

기존 Node v24.16.0 / macOS x64 / SQLite 3.53.0, in-memory 목업 1,000개·첫 조회 제외 30회 기록은 스냅샷 검증 캐시 전후 P50 10.08→5.78ms, P95 13.53→6.95ms였다. 첫 조회는 14.85→15.58ms로 개선되지 않았다. 기록 파일·측정 스크립트를 확인했으나 이번 문서 작업에서 성능 측정을 재실행하지 않았다.

기존 웹 목업·실제 API 표본 재생의 단회 결과는 변동이 있어 첫 목록 속도 개선율로 일반화하지 않는다. 네이티브 프레임·메모리·첫 표시·설치형 크기는 미측정이다. export 자산 크기는 APK 크기가 아니다.

## 8. 남은 수락 검증과 향후 변경 후보

### 구현된 기능에 필요한 수동 검증

1. 기기·OS·빌드 식별을 기록하고 탐색 → 저장 → 여행 생성 → 여러 지역/날짜 추가 → 순서·메모 → 프로세스 종료/재실행을 수행한다.
2. 비행기 모드에서 부팅·여행 열람·순서/메모 편집·재실행을 확인한다. 사진 캐시가 없는 경우 대체 표시와 기본 스냅샷을 비교한다.
3. 기간 축소의 항목별 이동·삭제·취소·중복 충돌, 저장 해제와 일정 삭제의 독립성을 확인한다.
4. 메모의 정상 초기 포커스 완료와 빠른 입력·취소·계속 편집을 별도 확인한다. TalkBack·VoiceOver로 초기/복귀·순서/오류 안내를 검사한다.
5. 두 언어·두 테마·실제 시스템 큰 글씨·모션 감소·기기 시간대 변경으로 핵심 화면을 확인한다. 날짜·외부 앱·이미지 캐시·전체 삭제도 확인한다.
6. 실제 사용자 DB 대신 기존 버전 검증용 DB로 설치 환경 업그레이드·기록 보존을 확인한다. iOS 실기기 실행과 릴리스 기기 성능을 별도로 기록한다.

### 향후 요구사항 후보 — 현재 구현 범위와 구분

- 검증된 번역 연결 정보 확보 후 언어 간 장소 연결 정책 검토
- 신분류와 공통 유형 관계 검증 후 사용자 필터 범위 결정
- 사용자 데이터 내보내기·백업·복원 필요성 검토
- 필요 시 API 키 보호용 프록시·Sentry 도입·실기기 성능 개선 설계

위 후보는 자동으로 다음 개발 범위가 되지 않으며 별도 요청·범위 합의가 필요하다.

## 9. 문서 공개·Preview·출처

README는 포트폴리오 소개, 이 명세는 제품 기준, AGENTS는 유지보수 지침이다. 2026-10-11의 사용자 승인에 따라 세 문서와 Preview 이미지를 Git에 포함한다. 그 밖의 docs/ 자료와 실제 환경변수는 계속 제외하며 비공개 자료로 향하는 링크를 공개 문서에 넣지 않는다.

2026-10-11에 사용자가 제공한 Android 한국어·다크 테마의 홈·탐색·여행 생성·여행 상세 이미지를 확인했다. 원본 파일의 확장자는 PNG였지만 실제 데이터는 JPEG이므로 assets/preview/home.jpg, explore.jpg, trip-create.jpg, trip-detail.jpg로 내용 변경 없이 복사했다. README에 화면 내용에 맞는 alt와 동일한 표시 너비로 연결했다. 화면에서 인증키나 눈에 띄는 개인정보는 확인되지 않았다. 이 이미지가 항목별 네이티브 검증 완료를 의미하지는 않는다.

공개 범위는 README.md, AGENTS.md, docs/PRODUCT_SPEC.md와 위 네 이미지다. 향후 Preview를 보완한다면 탐색의 장소 이름·저장 버튼이 보이는 장면과 여행 생성의 열린 달력 장면을 추가 촬영한다. 새 촬영은 키·개인정보 없는 데이터로 진행하고 실제 파일·alt·연결을 확인한다.
