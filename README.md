# Yeojeong · 여정

전국의 한국 여행지를 찾아 저장하고, 날짜별 방문 순서와 메모를 정리하는 한국어·영어 여행 앱입니다. 한국을 여행하는 국내 여행자와 영어 사용자가 관심 장소를 실제 여행 일정으로 연결할 수 있도록 만들었습니다.

검색 결과를 다시 찾거나 여러 지역의 장소를 따로 관리하는 번거로움을 줄이는 것이 목표입니다. 로그인과 자체 백엔드 없이 여행·저장 장소·메모를 기기의 SQLite에 보관합니다. 새로운 관광정보를 찾는 과정에는 인터넷과 TourAPI 키가 필요하고, 저장한 일정과 기본 장소 정보는 로컬에서 사용할 수 있습니다.

AI 코딩 도구를 구현·리뷰·테스트·문서 정리에 활용했습니다. 아래 결과는 코드와 실행한 검증을 근거로 기록했으며, 자동 검증과 사용자가 보고한 Android 수동 확인을 구분합니다.

## 설계에서 중점적으로 다룬 문제

### 한국어·영어와 접근성: 언어를 바꿔도 사용자의 기록을 지키기

**문제:** UI를 영어로 바꾸는 것과 관광 콘텐츠를 영어로 조회하는 것은 다른 작업입니다. 국문·영문 콘텐츠 ID가 같다고 가정하면 다른 장소를 열거나 저장 기록을 잘못 합칠 수 있습니다.

**선택:** 버튼·오류·접근성 문구는 번역 리소스로 관리하고, 새 관광 콘텐츠는 `KorService2` 또는 `EngService2`에서 조회합니다. 장소는 서비스와 문자열 콘텐츠 ID의 조합으로 식별합니다. 언어 간 연결이 검증되지 않은 저장 장소는 저장 당시 기본 정보 스냅샷을 유지하며 원문 언어를 안내합니다. 여행 이름·메모·검색어는 자동 번역하지 않습니다.

**확인:** 서비스 코드 변환·언어별 캐시·번역 키·날짜 포맷을 자동 테스트로 확인했습니다. 브라우저에서는 언어를 바꾼 뒤 저장 장소·일정·메모를 유지하고, 재실행 후 원문 스냅샷을 복원하는 흐름을 확인했습니다. 같은 장소의 국문·영문 자동 연결은 구현하지 않았습니다.

**문제:** 메모를 연 직후 변경 취소 확인창을 빠르게 열고 닫으면, 늦게 실행된 초기 포커스가 복귀 포커스를 덮어쓸 수 있었습니다.

**선택:** 공통 포커스 예약기가 새 영역이나 복귀 동작 이전의 예약을 취소하도록 했습니다. 정상 E2E는 초기 포커스 완료를 조건으로 기다리고, 빠른 조작은 대기 없이 별도 시나리오로 검사합니다.

**확인:** 수정 전 웹 빌드에서 복귀 실패를 재현했고, 수정 후 예약 경쟁 회귀 테스트와 브라우저 E2E가 통과했습니다. 버튼 역할·레이블·상태, 글자 배율·모션 감소 반영도 구현했지만 TalkBack·VoiceOver의 실제 낭독과 네이티브 포커스 복귀는 추가 확인이 필요합니다.

근거: [번역 리소스](./src/shared/i18n/messages.ts), [장소 변환](./src/shared/api/tour/placeAdapter.ts), [포커스 예약](./src/shared/accessibility/focusScheduler.ts), [포커스 회귀 테스트](./tests/focus.test.mjs).

### 재사용 가능한 디자인 시스템: 같은 동작을 같은 규칙으로 제공하기

**문제:** 화면마다 색상·입력·오류·날짜 선택을 만들면 언어 길이, 테마, 비활성 상태의 처리 방식이 달라집니다. 수기 날짜 입력은 잘못된 날짜를 만들기 쉽습니다.

**선택:** 의미 기반 색상·간격·타이포그래피·48 단위 터치 영역 토큰 위에 `Button`, `IconButton`, `TextField`, `DateField`와 로딩·빈 결과·오류·확인 UI를 구성했습니다. `DateField`는 여행 생성·수정·확인 날짜·기간 축소의 이동 날짜에 재사용하고 각 용도에 최소·최대 날짜를 전달합니다. 도메인 카드는 그 위에서 장소·일정의 동작을 조합합니다.

**확인:** 윤년·월 경계·선택 범위·색상 대비를 자동 테스트로 확인했습니다. 브라우저에서 두 언어 × 라이트·다크, 320px 폭, 1.6배 DOM 글씨 모의 확대와 달력 범위 제한을 검사했습니다. 이 결과는 기기의 실제 시스템 글자 확대 검증을 대신하지 않습니다.

근거: [디자인 토큰](./src/shared/theme/tokens.ts), [공통 날짜 UI](./src/shared/ui/DateField.tsx), [달력 규칙 테스트](./tests/datePicker.test.mjs).

### 성능과 안정성: 느린 응답과 저장 실패에도 일정을 유지하기

**문제:** 앞선 검색 응답이 늦게 도착하거나 추가 페이지가 중복 요청되면 최신 목록이 뒤바뀔 수 있습니다. 통신 실패 후 같은 검색어를 다시 제출해도 오류 상태 때문에 새 요청이 생략되는 문제도 있었습니다.

**선택:** 요청 취소와 세대 비교로 이전 응답을 무시하고, `RequestCache`로 같은 요청을 공유합니다. 서비스·언어·검색 조건·페이지를 캐시 키에 포함하며 TTL·개수 상한을 둡니다. 목록은 `FlatList`로 가상화하고 안정적인 장소 ID로 중복 제거합니다. 같은 조건의 명시적 재검색은 네트워크·시간 초과·HTTP 5xx 실패 후 새 요청을 실행하며, 진행 중 중복 제출과 인증·할당량 오류 재시도 차단은 유지합니다.

**확인:** 늦은 성공·실패 응답, 이전 조건의 추가 페이지, 동시 요청, 실패 → 같은 검색어 제출 → 성공을 자동 테스트로 확인했습니다. 브라우저 품질 검사에서는 느린 검색 뒤 빠른 검색, 추가 페이지 실패와 기존 목록 유지, 인증·할당량 안내를 확인했습니다.

**문제:** 순서 교환이나 여행 기간 축소는 여러 레코드를 함께 바꿉니다. 중간 실패가 일부만 저장되거나 범위 밖 일정을 조용히 삭제해서는 안 됩니다.

**선택:** SQLite 고유 제약·외래 키·날짜 범위 트리거와 버전별 마이그레이션을 사용합니다. 한 DB 연결의 작업 큐와 트랜잭션으로 변경을 묶고, 기간 밖 항목마다 이동·삭제를 명시적으로 선택하게 합니다. 오래된 수정 버전과 중복 이동은 저장을 거부합니다. 저장 해제·일정 삭제·최근 기록 삭제는 독립적입니다.

**확인:** 실제 Node SQLite 엔진으로 중복 저장, 기간 변경·순서 변경·COMMIT 실패 롤백, 기존 DB 마이그레이션과 파일 재연결을 확인했습니다. 실제 SQLite WASM을 사용하는 브라우저 E2E에서 오프라인 메모·순서 편집과 새 브라우저 프로세스의 복원을 확인했습니다. 사진·설명·운영 정보의 오프라인 다운로드는 보장하지 않습니다.

반복적인 스냅샷 JSON 검증에는 값의 내용과 메타데이터를 확인하는 캐시를 사용합니다. 기존 측정 기록에서 Node v24.16.0 / macOS x64 / SQLite 3.53.0의 in-memory DB, 목업 저장 장소 1,000개, 첫 조회를 제외한 30회 조건으로 조회 P50은 10.08→5.78ms, P95는 13.53→6.95ms였습니다. 첫 조회는 14.85→15.58ms로 개선되지 않았습니다. 이는 2026-10-09의 Repository 측정이며 현재 APK 속도·프레임·메모리 개선 수치로 일반화하지 않습니다.

근거: [탐색 상태](./src/features/explore/models/exploreStore.ts), [요청 캐시](./src/shared/cache/requestCache.ts), [DB 트랜잭션](./src/shared/database/database.ts), [기간 변경 규칙](./src/features/trips/services/tripRules.ts), [여행 테스트](./tests/trips.test.mjs), [저장 측정 스크립트](./scripts/measureStorage.mjs).

## 사용한 기술과 구조

- React Native `0.86.3`, Expo SDK `57`, React `19.2.3`, TypeScript `~6.0.3`, Expo Router `~57.0.25`
- `expo-sqlite`: 로컬 영속 저장·버전 마이그레이션, `expo-image`: 이미지 표시·캐시
- `expo-localization`과 자체 번역·Intl 포맷 함수: 언어·날짜·숫자 표시
- React Context / `useSyncExternalStore`와 자체 `RequestCache`: 공유 상태·서버 응답 캐시
- `expo-clipboard` / React Native `Linking`: 주소 복사·전화·홈페이지 연결
- Node 내장 테스트 러너·SQLite, TypeScript, ESLint, Chrome DevTools Protocol 기반 E2E, EAS Build 설정

외부 상태 관리·번역·스키마·테스트 프레임워크를 사용했다고 표시하지 않습니다. 공급자 응답은 자체 런타임 검사로 검증합니다.

```text
src/app/                 Expo Router의 얇은 라우트
src/features/            home, explore, places, library, trips, settings
src/shared/              UI, 토큰, i18n, API, 캐시, DB, 접근성
scripts/                 브라우저 검증·실제 API 표본·성능 측정
tests/                   도메인·API·저장·경쟁 회귀 테스트
```

화면에서 Hook을 통해 상태·동작을 연결하고, 업무 규칙과 Repository가 API 또는 SQLite에 접근합니다. 스냅샷과 연결은 기능 간 공통 경계에서 공유합니다.

## 로컬 실행

현재 검증 환경은 Node.js `24.16.0`과 npm입니다. `package-lock.json`을 유지합니다.

```bash
npm ci
cp .env.example .env
```

발급받은 TourAPI 키를 복사한 로컬 `.env`에 입력합니다. 공통 키를 사용하거나, 서비스별 키가 다르면 해당 언어 전용 키를 설정합니다. 전용 키가 공통 키보다 우선합니다.

```dotenv
EXPO_PUBLIC_TOUR_API_KEY=
EXPO_PUBLIC_TOUR_API_KO_KEY=
EXPO_PUBLIC_TOUR_API_EN_KEY=
```

`.env.example`은 변수 이름만 제공하므로 복제만으로 실제 관광정보 조회가 가능해지는 것은 아닙니다. 빈 키에서는 설정 오류를 안내합니다. `.env`는 Git에 포함하지 않으며, `EXPO_PUBLIC_*`는 번들에서 확인 가능한 클라이언트 값입니다.

```bash
npm start
# 플랫폼별 개발 서버
npm run android
npm run ios
npm run web
```

`android`와 `ios` 명령은 Expo 개발 실행이며 설치형 APK 생성 명령이 아닙니다. 호환 실행 환경과 Android SDK·에뮬레이터 또는 연결 기기 등이 필요합니다. 현재 작업 트리의 `app.json` 아이콘·로컬라이제이션·SQLite 설정을 네이티브 빌드에 반영해야 합니다.

## Android Preview APK 빌드

현재 `eas.json`의 `preview`는 `developmentClient: false`, 내부 배포, `environment: preview`, Android `buildType: apk`입니다. EAS CLI 요구 버전은 `>=24.8.0`입니다.

1. 자신의 Expo 계정과 EAS 프로젝트를 준비하고, 복제한 프로젝트의 연결 설정을 확인합니다. 원 작성자의 프로젝트 접근 권한이 자동으로 부여되지는 않습니다.
2. EAS의 `preview` 환경에 위 TourAPI 변수 이름으로 값을 설정합니다. 로컬 `.env`가 원격 빌드에서도 자동 제공된다고 가정하지 않습니다. `eas.json`에는 실제 키를 적지 않습니다.
3. 로그인 후 Preview 빌드를 실행합니다. 아래 명령은 기존 `eas.json`을 사용하는 EAS CLI 명령이며 npm 스크립트가 아닙니다.

```bash
npx eas-cli@24.8.0 login
npx eas-cli@24.8.0 build --platform android --profile preview
```

빌드 결과의 APK를 Android 기기에 설치해 확인합니다. 프로젝트·서명·환경변수 구성에 따라 추가 설정이 필요합니다. 이번 문서 작성에서는 원격 EAS 빌드를 실행하지 않았습니다.

## 검증 명령

```bash
npm run typecheck
npm run lint
npm test
npx expo export --platform all --output-dir dist
npm run test:e2e
npm run test:quality
```

브라우저 검증은 정적 출력 `dist`를 사용합니다. 다른 출력 위치는 `YEOJEONG_WEB_BUILD`로 지정할 수 있습니다. 기본 Chrome 경로는 macOS의 Google Chrome이며 다른 환경은 `CHROME_BIN`으로 실행 파일을 지정합니다. 로컬 포트 `8088`·`9223`을 사용하므로 브라우저 검증을 동시에 실행하지 않습니다. 테스트는 검증용 임시 브라우저 프로필을 생성하고, 복원용 프로필 경로를 `/tmp`에 남깁니다.

별도 조사 명령은 `npm run probe:tour`, `npm run probe:performance`, `npm run measure:storage`, `npm run measure:web`입니다. `probe:*`는 실제 키와 네트워크를 사용하고 호출량을 소비하므로 자동 테스트와 구분해 실행합니다. `probe:tour`의 `--extended`, `--supplement`, `--inspect` 옵션은 표본·오류·이미지 검증 범위를 변경합니다. CLI 실호출에는 TLS 검증을 유지한 `curl`이 필요합니다.

웹 SQLite는 WASM·Worker·교차 출처 격리가 필요합니다. 개발 서버와 검증 스크립트는 COOP `same-origin` / COEP `credentialless` 헤더를 제공합니다. 별도 정적 호스팅도 이 헤더와 WASM MIME을 구성해야 합니다.

## 알려진 제한과 개선 과제

- Android 동작은 사용자의 수동 확인 보고가 있지만 최신 빌드별 상세 증거는 부족합니다. 기기·OS·빌드를 기록하고 기간 축소, 재실행·비행기 모드, DB 업그레이드, 메모의 빠른 조작을 다시 확인할 필요가 있습니다.
- iOS, TalkBack·VoiceOver, 실제 큰 글씨, 네이티브 이미지 캐시·외부 앱 연결·성능은 추가 실기기 검증 대상입니다.
- 국문·영문 장소 자동 연결은 미구현입니다. 검색에서는 지역 조건만 결합하며 관광타입 필터를 제공하지 않습니다. 신분류 선택 UI도 없습니다.
- 오프라인 범위는 여행·순서·메모·기본 스냅샷입니다. 새 검색, 상세 설명·이용 정보·사진 다운로드는 온라인 또는 기존 캐시에 의존합니다.
- 로그인·동기화·내보내기·백업은 없습니다. 앱 삭제나 저장 공간 삭제 시 로컬 기록을 잃을 수 있습니다.
- 웹 실제 API CORS, Web Locks 미지원 환경의 여러 창, 전체 웹 오프라인 부팅은 확인하지 않았습니다.
- 구조화 로그는 고정 이벤트·영역·오류 분류·시각을 로컬에 출력합니다. Sentry 연동·외부 전송은 없습니다.
- 직접 API 호출 구조에서 키를 앱 번들로부터 숨길 수 없습니다. 프록시는 향후 별도 범위이며 현재 자체 백엔드는 없습니다.

## 관광정보·이미지 출처

관광정보와 장소 사진은 [한국관광공사 TourAPI](https://api.visitkorea.or.kr/)에서 제공받습니다. 이미지의 원본 주소와 공급자 이용 유형을 보존하며, 화면·설정에서 출처와 [공공누리 이용 안내](https://www.kogl.or.kr/info/userGuide.do)를 제공합니다.

이미지는 `contain`으로 표시하고, HTTPS 다운로드가 확인된 관광공사 CDN의 제한된 경로만 표시용 HTTPS로 정규화합니다. 다른 HTTP 주소를 무조건 치환하거나 없는 사진·운영 시간·요금을 임의로 채우지 않습니다. 개별 이미지의 이용 유형과 변경금지 조건은 별도로 확인해야 하며, 출처 표기만으로 모든 재사용이 허용된다고 주장하지 않습니다.
